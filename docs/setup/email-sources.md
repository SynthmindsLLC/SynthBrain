# Email sources — Gmail + iCloud Mail

Two adapters. **Both** route every message through
`brain/core/email_filter.py` so marketing / newsletters / bulk noreply mail
never reach the brain. What survives is personal + work + transactional
(receipts, invoices, bookings).

The filter is auditable — the verdict's `stage` field tells you why each
message was kept or dropped (`list-unsubscribe`, `hard-block-domain`,
`allowlist`, `own-domain`, `transactional`, `llm`, or `default`).

---

## Gmail (work + personal Google accounts)

### 1. Add the scope to your existing OAuth client

If you already minted a Google OAuth refresh token for Drive/Calendar/People,
add `https://www.googleapis.com/auth/gmail.readonly` to the same client.

1. Google Cloud Console → **APIs & Services → OAuth consent screen → Scopes** →
   Add `https://www.googleapis.com/auth/gmail.readonly`.
2. **Enable Gmail API** under **APIs & Services → Library**.
3. Re-mint the refresh token (OAuth Playground): in step 1, paste all your
   scopes including the new one, then exchange and copy the new
   `GOOGLE_OAUTH_REFRESH_TOKEN` into `second-brain/.env.local` and your
   GitHub Actions secrets.

### 2. Run it

```bash
cd second-brain
python -m brain.cli --entdb ./entities.db ingest --adapter gmail
# Optional: bias the filter with the LLM tiebreaker for messages
# in the gray zone (needs ANTHROPIC_API_KEY).
export ANTHROPIC_API_KEY=sk-ant-...
python -m brain.cli --entdb ./entities.db ingest --adapter gmail
```

Incremental sync is automatic after the first run via Gmail's `historyId`.

### 3. Two accounts?

Mint a separate refresh token per Google account and run the adapter twice
with different env files:

```bash
GOOGLE_OAUTH_REFRESH_TOKEN=... \
  python -m brain.cli --entdb ./entities.db ingest --adapter gmail
GOOGLE_OAUTH_REFRESH_TOKEN=... \
  python -m brain.cli --entdb ./entities.db ingest --adapter gmail
```

## iCloud Mail (no public API — IMAP w/ app-specific password)

iCloud has no public REST API. The supported path is IMAP TLS over an
**app-specific password** generated by Apple.

### 1. Mint an app-specific password

1. Sign in at https://appleid.apple.com.
2. **Sign-In and Security → App-Specific Passwords → Generate an
   app-specific password.**
3. Label it `SynthBrain IMAP`.
4. Copy the 19-character password (Apple shows it ONCE).

This password is restricted to mail-account IMAP/SMTP — it can't be used
to change your Apple ID or trigger a passkey reset.

### 2. Add to `.env.local`

```bash
IMAP_HOST=imap.mail.me.com
IMAP_PORT=993
IMAP_USERNAME=you@icloud.com         # or @me.com
IMAP_PASSWORD=xxxx-xxxx-xxxx-xxxx    # the app-specific password
IMAP_FOLDER=INBOX
IMAP_OWN_DOMAINS=synthminds.ai       # comma-separated; auto-pass these senders
```

### 3. Run it

```bash
cd second-brain
python -m brain.cli --entdb ./entities.db ingest --adapter imap
```

Subsequent runs use the UIDVALIDITY + UID watermark stored in the
checkpoint table, so only new messages are fetched.

If you have multiple iCloud aliases (`@me.com`, `@mac.com`), they all share
one IMAP account — set `IMAP_USERNAME` to the canonical Apple ID address.

### 4. Other IMAP providers

The same adapter works for Fastmail (`imap.fastmail.com:993`),
generic cPanel, etc. Override `IMAP_HOST` / `IMAP_PORT` accordingly.

## What the filter keeps and drops (by example)

| Sender / subject | Verdict | Stage |
|---|---|---|
| `Jeff Torres <jeff@acme.com>` (in your Contacts) | KEEP `personal` | `allowlist` |
| `wes@synthminds.ai` (own-domain) | KEEP `work` | `own-domain` |
| `receipts@store.com` "Receipt #1234" | KEEP `transactional` | `transactional` |
| `noreply@bigsite.com` anything | DROP `newsletter` | `hard-block-local` |
| `alex@klaviyo.com` anything | DROP `marketing` | `hard-block-domain` |
| Any sender with `List-Unsubscribe` header | DROP `marketing` | `list-unsubscribe` |
| `random@unknown.com` "Hi there" (no LLM) | DROP `unknown` | `default` |
| `random@unknown.com` "Hi there" (LLM "personal") | KEEP `personal` | `llm` |

The LLM tiebreaker only runs on messages that pass the cheap stages and
have no allowlist signal — typically <5% of inbox volume after the hard
rules clear ~80%.

## GitHub Actions cron (already wired)

`.github/workflows/sync-entities.yml` runs hourly. Email steps are gated
on these repo secrets so they're opt-in:

| Secret | Required for |
|---|---|
| `GMAIL_ENABLED` (value: `true`) | Gmail step |
| `ICLOUD_IMAP_USERNAME` + `ICLOUD_IMAP_PASSWORD` | iCloud step |
| `IMAP_OWN_DOMAINS` | optional override for `IMAP_OWN_DOMAINS` |
| `ANTHROPIC_API_KEY` | LLM tiebreaker (recommended) |

If those secrets aren't set, the workflow skips the email steps
gracefully — only Calendar + People sync runs.
